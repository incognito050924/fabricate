# 결정 0001 — 계약 증거 어휘 → 게이트 증거 종류 매핑

날짜: 2026-07-25 · 상태: 확정 (조각 2 착수 전 고정)

## 문제

창립 계약(`contract/criteria.json`)의 `evidence_required` 어휘는 test(68건)·doc(6건)·log(1건)인데,
게이트의 증거 종류는 test·command·file·observation·repro다. doc·log의 매핑을 고정하지 않으면
그 7개 조건은 증거 게이트로 닫을 길이 없거나, 조각 2에서 판정 기준을 쓰는 에이전트가 그때그때
편한 종류로 밀어넣는다.

## 결정

| 계약 어휘 | 건수 | 게이트 종류 | 판정 방식 |
| --- | --- | --- | --- |
| test | 68 | test | run |
| doc | 6 | file | rescan |
| log | 1 | file | rescan |

코드 상수: `src/gate/evidence.ts`의 `CONTRACT_EVIDENCE_KIND`. 계약이 쓰는 어휘 전부가 이 상수에
있는지, 그리고 doc→file·log→file이 유지되는지는 테스트가 `criteria.json`을 직접 읽어 검사한다 —
계약에 새 어휘가 나타나면 테스트가 깨져 매핑 갱신(과 이 문서의 개정)을 강제한다.

## 근거

- **doc (ac-33·ac-36·ac-38·ac-39·ac-40·ac-E2, 전부 DESIGN 노드)**: 여섯 조건 모두 완료기준이
  spec/스키마 문서 산출이다. 문서는 디스크 위 산출물이고 검증은 그 산출물을 다시 스캔하는 것 —
  rescan/file. 문서 품질에 대한 사람 판단이 필요한 부분이 있다면 그것은 증거 종류가 아니라 별도의
  human 판정 기준으로 분리한다(종류를 완화하는 우회로 쓰지 않는다).
- **log (ac-8)**: 조건 문안 스스로 결정적 검사 대상을 "파일 존재·마커 순서·확인 레코드"로 선언한다 —
  로그 파일이라는 산출물의 재스캔이다 → rescan/file. "진짜 도그푸드인지·스팬의 의미적 실재"는 문안이
  잔여로 명시했으므로(log-evidence AC — 게이트 아님) 증거 종류 매핑의 대상이 아니다.
- **observation·repro로 보내지 않는 이유**: 둘 다 human 판정 전용 종류다. doc·log 7건은 문안이
  결정적 검사를 지정하므로 human으로 보내면 판정이 오히려 약화된다.

## 파급

- 조각 2에서 69개 판정 기준을 쓰는 에이전트는 `evidence_required`를 이 매핑으로만 번역하고,
  69행 판정표에 이 결정을 링크한다.
- 이 매핑을 바꾸려면 이 문서를 개정하고 대조 테스트를 함께 바꿔야 한다 — 조용한 변경은 불가능하다.
